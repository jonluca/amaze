# AMAZE!!! reference audit

Audited and implementation status updated 2026-09-06. This is a public-reference audit, not an installed-app walkthrough. Baseline means the Prism Roll implementation at the start of this audit. The requested feature set was materially broader than the initial app. The table separates implemented behavior from remaining verification; [VALIDATION.md](VALIDATION.md) records final test and runtime outcomes.

## Evidence and confidence

Both reported **6.2.2**, released **2026-08-17**. Release notes identify themes, collectible balls, bonus coin levels, competitive matchups, and daily rewards. Version 5.4.0, dated 2025-04-02, identifies Duel as PvP. The information panel lists Game Center and in-app purchases.
- **Current official images:** Visually inspected the four iPhone screenshots returned by Apple. These are promotional screenshots, not a live capture. - **User requirements:** The user directly identifies unlimited, timed, and limited-move modes; ads for hints and more time; challenges; coins; daily streaks; and better fidelity. These are requirements even where official public descriptions omit details.
- **Historical mobile corroboration:** [Polish App Store review, 2025-01-03](https://apps.apple.com/pl/app/amaze/id1452526406) describes timed and limited-move modes, hints, and ad-assisted progression. A review is user testimony, not current developer documentation.

## Feature comparison

| Swipe-to-paint 3D maze | Current listing/images | Present; stops at walls and fills traversed cells | Deterministic solvable generation, wall-stop swipes, saved partial runs, and a revised SceneKit world. Build 3 accepts swipes throughout gameplay space at a 12-point directional threshold before lift-off, while preserving controls and sheets. Ordered move events retain rapid turns and reject stale snapshots; reset/modal transitions invalidate old touches. These input choices are original, not measured reference thresholds. |
| Native iOS navigation and controls | User polish request | Custom tab strip, cards, and buttons | Build 3 uses native TabView/NavigationStack navigation, toolbars, segmented Picker, List, and Form screens. Accessibility text sizes preserve a visible board with scrollable controls. Native-control and large-text UI checks pass; this is a platform design decision rather than reference UI parity. |
| Unlimited / Classic | User; current listing | Endless mode present | Classic has unlimited time/moves and its own progression. Each mode resumes its own run; unlocked levels can be replayed. |
| Limited moves | User; historical mobile review | Move Challenge present | Dedicated selector, remaining-swipe counter, failure/retry, and rewarded +3 moves. Budgets derive from a verified covering route plus a margin. The budget and +3 allowance are original balance choices. |
| Time-based mode | User; historical mobile review | Missing | Time Rush has separate progression, first-move countdown start, elapsed-time accounting, timeout/retry, and saved remaining time. Background, hidden play, settings, ads, and consent screens pause the clock. One maze per round; its duration is `max(30, solutionMoves × 2 + 15)` seconds, an original balance choice rather than verified reference timing. |
| Rewarded hint | User; historical hint corroboration | Hints were free; rewarded ads only doubled points | Production hint buttons request an optional video. Only the earned-reward callback applies the captured run/position-specific request. Duplicate, stale, and expired-run requests are rejected. Google test-ad runtime outcome belongs in [VALIDATION.md](VALIDATION.md); debug UI hint shortcuts are not ad verification. |
| Rewarded extra time | User | Missing | Optional video adds 30 seconds and can revive a timed-out run. Extra time is applied once per request; early dismissal, unavailable inventory, and presentation failure grant nothing and release the pause. +30 is our balance choice; the reference amount is unknown. |
| Challenges | User; listing | Only sequential move levels | A Challenges hub contains a deterministic daily move maze worth 100 coins, daily rewards, Duel, and four claim-once milestones for regular completions, timed completions, and skin ownership. Daily mazes and milestone rewards are separate from regular level credit. |
| Coins and skins | User; notes/images | Eight purchasable skins used a points balance | Twelve ball skins, coin prices, affordability states, selection, and ownership persistence. New regular completions award 50 coins; a voluntary completion video can add 50 once. Existing balances, ownership, and partial runs migrate into the combined snapshot. |
| Bonus coin levels | Current notes | Missing | Every fifth Classic level contains three collectible coins worth five each, with animated pickups and a counter. A persisted per-tile ledger prevents collecting them again after replay or relaunch. This cadence and economy are original. |
| Daily rewards / streak | User; current notes/images | Missing | Local-calendar daily claims award 25 coins, increasing by five per consecutive day to a 55-coin cap. Missing a day resets the streak; duplicate claims and clock rollback are rejected. Active midnight refresh retires an expired daily run with a notice, preserves the solo run, and rejects input/rewards captured for the old daily. All three midnight lifecycle regressions pass in the final simulator suite. |
| Board themes | Current notes/images | One pale board style | Four original persisted themes: Aurora, Timber, Porcelain, and Midnight. Connected beveled walls, recessed paths, glossy balls, contact shadows, procedural textures, rolling motion, paint effects, and 3D collection previews replace the initial presentation. Build 3 moves texture generation off the UI actor, gates reveal/input on a prepared first frame, and uses a smaller 68%-width/78%-height camera fit. A matching dark launch background and [original generated icon](Design/README.md) complete the polish checkpoint. No reference artwork is reused. |
| Interstitial advertising | Current listing; user | SDK integration already present | Google Mobile Ads and UMP remain integrated. Every fourth completion can show an available interstitial between levels; a rewarded video resets the interval. No Ads entitlement suppresses interstitial loading/display. Production app/rewarded/interstitial IDs are verified and configured for build 2; Debug retains test units. Requests use non-personalized ads and restricted data processing with publisher first-party ID and personalization disabled. Sample SDK requests and US opt-out were verified. Production ad serving awaits Google approval and public-store linking; European consent delivery remains unverified. |
| Duel / PvP | Current official version history | Missing | Real Game Center matchmaking, invitations, seed/UUID handshake, live opponent progress, and reliable host-decided results are implemented. Disconnect/background cleanup preserves solo progress. No bots or coin payouts. This is a casual peer-hosted race; two authenticated accounts and provisioned Game Center must still verify the complete connection/result flow. |
| No Ads / purchases | Current listing | No StoreKit integration | StoreKit 2 loads the actual non-consumable product and its localized price, purchases/restores it, and tracks verified entitlement/revocation updates. No hardcoded production price or fake unlock. The entitlement removes between-level ads while voluntary videos remain available. The App Store product is created. All three local StoreKit tests passed on iOS 26.1, covering purchase, restore, revocation, pending Ask to Buy, and UI; App Store sandbox and production purchases remain unverified. Legacy product labels alone do not justify inventing other game systems. |
| Music mode | Developer case study, 2020 | Only movement sounds | A distinct music mode is not implemented. Movement sounds remain available, but are not presented as music-mode parity. Current reference availability remains unverified. |

## Validation checkpoint

The current local project is **1.0.0 (3)**, being prepared for release. Its polish checkpoint passed **69 unit/state tests** in `PolishTests-2`, followed by **five renderer regressions and seven gameplay UI flows** in `PolishTests-3`, plus the final rapid-input smoke test. Counts overlap; the earlier run's four UI selector failures were corrected before the successful rerun. Coverage includes 600 synchronous moves, stale-snapshot and reset protection, short flicks outside the board, native controls, camera bounds, first-frame readiness, and accessibility text layout. Local state-processing measurements exclude rendering and are detailed in [VALIDATION.md](VALIDATION.md). No build 3 upload, distribution, or submission outcome is claimed at this checkpoint.

The earlier feature-expansion checkpoint passed **57 iPhone simulator tests** (52 engine/state and five UI flows), plus **two iPhone SE UI tests**. At that checkpoint the pure package passed 31 tests; the generator audit covered 9,000 regular and 365 daily boards, including 600 coin boards. After the later geometry-test platform-guard correction, the current pure package compiles and discovers 31 tests without a claimed full rerun. Actual Google test ads granted a hint and restored an expired timer to 30 seconds while preserving paint and position. Timber, collection, challenges, journey, completion, and small-screen views were inspected. Debug simulator and unsigned Release arm64 builds passed at that checkpoint.

Subsequent release work passed three local StoreKit tests on iOS 26.1; the fixture encountered a StoreKit runtime failure on iOS 26.5. The final production archive used Xcode 26.6 and iOS SDK26.5, followed by local distribution signing and strict signature/entitlement verification. Apple accepted version **1.0.0 (2)** as VALID; the app and No Ads are now **Waiting for Review**. The same build is **In Beta Testing**, with the account holder invited to a private internal group. Support/privacy pages are published and verified, as are App Privacy and the store metadata/screenshots. Actual sample-ad request controls and US opt-out were exercised; production ad serving, European consent delivery, two-account multiplayer, and App Store sandbox purchases remain unverified. See [VALIDATION.md](VALIDATION.md) for artifacts and exact release boundaries.

## Visual findings and acceptance

The official images use recessed corridors, substantial wall depth, textured surfaces, strong contact shading, metallic balls, saturated paint, and visible motion/splatter accents. A compact control strip leaves the maze visually dominant. The initial [Prism Roll screenshot](artifacts/prism-roll.png) has disconnected pale square tiles, subdued material contrast, weak contact shadows, and a large amount of chrome around the board. SceneKit presence alone did not establish comparable fidelity.

The updated implementation has connected painted paths, beveled architecture, stronger lighting and ball highlights, continuous rolling motion, contact shadows, original material variation, and finish effects. Build 3 pairs a smaller board with native dark navigation and controls, coin/streak toolbars, and dedicated Challenges/Collection/Journey screens. Texture preparation and a first-frame readiness gate cover scene startup, including replay. Rendered screenshots and runtime observations, rather than the presence of SceneKit code, determine visual acceptance; those artifacts and final checks belong in [VALIDATION.md](VALIDATION.md). This is an original art direction and does not establish pixel or feature parity with an installed reference build.

## Limits on parity claims

Public evidence does not reveal exact current iOS timers, extension amounts, ad frequency, mode unlock levels, daily reset policy, challenge schedule, full cosmetic inventory, economy, matchmaking internals, purchase entitlements, or every remote-config variant. These must be labeled implementation decisions, not reverse-engineered reference values. New features require runtime verification; a successful build alone does not prove ads, purchases, or multiplayer work with production accounts. Installing and exploring the current reference app on a real device remains necessary before claiming **all features match**.
